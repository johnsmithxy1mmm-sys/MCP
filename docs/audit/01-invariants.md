# 01 — Инварианты (фаза 1)

Утверждения, которые ДОЛЖНЫ быть истинны всегда. Колонка «Проверка»:
`код` — enforced в рантайме, `тест` — есть регрессия, `—` — не проверяется нигде.
Нарушенные инварианты вынесены в реестр находок как `INV-*`.

## INV-001 — Один подписанный платёж расчитывается дважды (TOCTOU)

**Файл:** `src/predmarket_mcp/billing/middleware.py:135-145`

```python
if self.nonces.is_used(fingerprint):      # ← T1: проверка
    raise PaymentError("payment_reused")
receipt = self.facilitator.verify_and_settle(payment, requirement)   # ← НЕОБРАТИМО
if not self.nonces.mark_used(fingerprint):  # ← T2: захват, слишком поздно
    raise PaymentError("payment_reused")
```

Комментарий в коде утверждает «mark_used after verify closes the race» — он
закрывает гонку на **выдачу результата**, но не на **расчёт**. `check_x402`
вызывается из пула потоков (`anyio.to_thread.run_sync`), то есть параллельно
по-настоящему.

**Измеренный результат репро (2 потока, один заголовок):**
```
расчётов у фасилитатора (списаний с плательщика): 2
успешных вызовов отдано клиенту:                  1
квитанций сохранено:                              1
```

**Последствия:** плательщик списан дважды, услуга оказана один раз, в книгах
одна квитанция. `/revenue` покажет `discrepancy_usd = 0` — **оператор не увидит
проблему никогда**. Необратимо (реальный перевод USDC). Redis-путь (`SET NX`)
атомарен только внутри `mark_used`; сама последовательность проверка→расчёт
остаётся неатомарной на обоих бэкендах.

## INV-002 — Любой вызывающий читает данные любого клиента (IDOR)

**Файлы:** `src/predmarket_mcp/resources.py:31-35` (alerts), `:57-62` (portfolio);
корень — `src/predmarket_mcp/tools.py:69-71`.

Проверка владельца сравнивает **параметр ресурса, подконтрольный вызывающему**, с
**идентификатором, взятым из заголовка, тоже подконтрольного вызывающему**:

```python
if client_id != caller_id():      # caller_id() = headers["x-client-id"]
    return {"error": "forbidden"}
```

Атака: выставить `x-client-id: <жертва>` и запросить `portfolio://<жертва>`.
Обе стороны сравнения равны — доступ разрешён.

**Измеренный результат репро:**
```
ALERTS    -> ПРОЧИТАНО
PORTFOLIO -> ПРОЧИТАНО, сделок: 1, размер: $5000.0
```

**Последствия:** утечка оплаченной аналитики (alerts) и **торговой стратегии**
клиента (portfolio: рынки, стороны, размеры, P&L). Дополнительно — обход лимитов
A6/A7 и возможность отравить чужую статистику на лидерборде, записав сделки от
его имени. Включённый OAuth не спасает: `x-client-id` имеет приоритет над
`authorization` в `_client_id()`.

## INV-003 — Отказ метеринга уничтожает уже оплаченный успешный вызов

**Файл:** `src/predmarket_mcp/billing/middleware.py:192-213` (блок `finally`).

Запись метеринга выполняется в `finally` **без обработки исключений**. Если она
падает (диск полон, БД заблокирована, таймаут потока), исключение выходит из
`finally`, отменяя `return result` и **подменяя** исходное исключение инструмента.

**Измеренный результат репро:**
```
клиент получил ОШИБКУ: ToolError: disk I/O error
(инструмент при этом отработал успешно — результат потерян)
```

**Последствия в платном режиме:** x402-middleware расчитывает платёж **до**
исполнения инструмента. Значит: деньги списаны → инструмент отработал → клиент
получил ошибку → `usage`-записи нет. Оператор не узнает ни о списании, ни о
неоказанной услуге. Также маскирует настоящие ошибки инструментов при
деградации хранилища (диагностика становится ложной).

## INV-006 — `gross_edge` и `realizable_edge` в одном ответе несопоставимы (SUSPECTED)

`gross_edge` — абсолютная величина на единицу баскета (`payoff − unit_cost`),
`realizable_edge` — доля от вложенного капитала (`profit / capital`). Совпадают
только при `unit_cost ≈ 1`. Агент, сравнивающий их напрямую (естественное
действие — оба в одном объекте), получит искажение тем большее, чем дальше
`unit_cost` от единицы. Требует решения: привести к одной величине или
переименовать. Доказательства искажения в реальном сценарии пока нет.

## INV-007 — Гонка на интервале якорения (SUSPECTED, low)

`AnchorStore.maybe_anchor`: `latest()` → `anchor.submit()` → `_save()` без
удержания лока на всём протяжении. Два параллельных обращения к
`/track-record` при `ANCHOR_ENABLED=on` могут отправить **две транзакции** в
чейн для одного корня. Стоимость — газ, необратимо. Репро не написан:
`/track-record` вызывается редко, вероятность низкая.

# Инварианты без единого теста (кандидаты фазы 2)

- **P6** — согласованность единиц измерения по всем границам (проценты/доли,
  секунды/мс, контракты/доллары). Три из четырёх найденных ранее money-багов
  были именно рассогласованием единиц.
- **N5** — монотонность времени: `time.time()` и `time.monotonic()` смешаны
  между модулями; поведение при переводе часов и на границе суток UTC не
  проверялось.
- **M7** — `fillable ≤ requested` нигде не утверждён явно.
- **P1** — клэмпы [0,1] расставлены точечно; системной property-проверки нет.
- Устойчивость парсеров к враждебному входу (ReDoS в регулярках `entailment`,
  `basis`; глубоко вложенный JSON от площадок) — не проверялась.
